# OKX Scalp Signal Bot

Скринер альтов на OKX USDT-SWAP по стратегии "ранний импульс → long → быстрый выход".
Только анализ и сигналы в Telegram. **Ордера бот не отправляет** — открытие позиции всегда
делает пользователь вручную (в коде нет ни одного вызова торгового эндпоинта OKX).

## Что делает

- Каждые `SCREEN_INTERVAL_SEC` секунд (по умолчанию 120) сканирует все `*-USDT-SWAP`:
  фильтрует по изменению цены за 24ч, объёму, открытому интересу (OI) и его динамике.
- Для прошедших фильтр пар считает RSI(15m/1H), MACD(15m), Supertrend(15m/1H), funding.
- Скорит сетап 0–10, при score ≥ `MIN_SCORE_TO_SIGNAL` (по умолчанию 7) шлёт сигнал в Telegram
  строго по формату из ТЗ (вход/стоп/тейки/плечо/маржа/причины/риск).
- Если ключи OKX read-only заданы — дополнительно раз в цикл читает открытые позиции
  (`GET /account/positions`, только чтение) и шлёт алерты: TP1 достигнут, цена у стопа,
  разворот Supertrend 15m, закрытие позиции (плюс/минус). После 2 убытков подряд ставит
  паузу на новые сигналы на `LOSS_STREAK_PAUSE_MIN` минут.
- Состояние (история OI, кулдауны сигналов, серия убытков) хранится в `state.json` рядом
  с проектом — переживает перезапуск.

## Установка

```bash
npm install
```

```bash
cp .env.example .env
```

Заполни `.env` (см. ниже, как получить ключи).

```bash
npm start
```

Бот — постоянный процесс, работает в бесконечном цикле. Останов: `Ctrl+C`.

## Веб-дашборд

Вместе с ботом поднимается локальный веб-интерфейс: `http://localhost:3000`
(порт меняется через `WEB_PORT` в `.env`).

- **Статус** — работает/на паузе, время последнего скрининга, кол-во кандидатов,
  настроен ли Telegram/OKX.
- **Статистика** — всего сигналов, открыто, закрыто, **winrate**, средний PnL закрытых
  сделок, текущая серия убытков.
- **Настройки стратегии** — все пороги из `.env` (фильтры скрининга, RSI-зоны,
  Supertrend, кулдауны, плечо/маржа/мин.скор) редактируются прямо в браузере и
  применяются на следующем цикле скрининга **без перезапуска бота**. Сохраняются
  в `settings.json` (имеет приоритет над `.env` при следующем запуске).
- **Таблица ордеров** — журнал всех отправленных сигналов с исходом (открыт / TP1 взят /
  закрыт в плюс / закрыт в минус) — используется для расчёта winrate. Статус ордера
  обновляется автоматически только если заданы OKX read-only ключи (мониторинг позиций).

Ключи OKX/Telegram в дашборде не отображаются и не редактируются — только через `.env`.

## Деплой на Dokploy

В репозитории есть `Dockerfile` — Dokploy подхватит его автоматически при типе
приложения **Dockerfile** (или **Docker Compose**, тогда используй `docker-compose.yml`).

1. В Dokploy: **Create Application** → **Docker Compose** или **Dockerfile** → указать
   этот git-репозиторий и ветку `main`. Build path — корень репо.
2. **Environment Variables** — задать в UI Dokploy (не коммитить `.env`!):
   `OKX_API_KEY`, `OKX_API_SECRET`, `OKX_API_PASSPHRASE`, `OKX_DEMO`,
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, плюс при желании любые из
   `SCREEN_INTERVAL_SEC`/`CHANGE24H_MIN`/... (см. [.env.example](.env.example)).
   `DATA_DIR` уже выставлен в `/app/data` образом — трогать не нужно.
3. **Volume/Mount** — примонтируй volume на `/app/data`, чтобы `state.json`/`settings.json`
   (история OI, кулдауны сигналов, журнал ордеров, настройки из веб-UI) переживали редеплой.
   Без volume при каждом деплое статистика/winrate обнулятся.
4. **Port** — контейнер слушает `3000` (или значение `PORT`, если Dokploy его пробрасывает
   автоматически — код это учитывает). `docker-compose.yml` намеренно **не публикует**
   порт на хост (`expose`, не `ports`) — Dokploy сам маршрутизирует трафик через встроенный
   Traefik по внутренней docker-сети. В настройках приложения в Dokploy укажи Container Port
   `3000` и подключи домен/поддомен — жёстко биндить `0.0.0.0:3000` на хосте не нужно и не стоит:
   так порт может занять любое другое приложение на той же ноде и деплой упадёт с
   `port is already allocated`.
5. **Health check** — путь `/health`, ответ `200 ok`, уже прописан в `Dockerfile` (`HEALTHCHECK`)
   и как отдельный роут — можно использовать в Dokploy health-check настройках.
6. Деплой. Логи цикла (`скрининг: N кандидатов`, отправленные сигналы) смотри во вкладке
   **Logs** приложения в Dokploy; дашборд — по домену, который выдал Dokploy/Traefik.

Локально (без Dokploy/Traefik) `expose` не даёт достучаться с хоста — на время теста
добавь публикацию порта:

```bash
docker compose run --rm --service-ports signals-bot
```

или временно верни `ports: ["3000:3000"]` в `docker-compose.yml`.

## Как получить OKX API ключ (read-only)

1. Зайди на okx.com → профиль → **API** → **Create API Key**.
2. Права доступа: включи **только "Read"** (чтение). **Не включай Trade и Withdraw** —
   бот не должен и не может торговать этими ключами.
3. Если хочешь потестить сначала без риска — можно создать ключ в **Demo Trading**
   (переключатель в верхней панели OKX) и поставить `OKX_DEMO=true` в `.env`.
4. Впиши `API Key`, `Secret Key`, `Passphrase` в `.env` (`OKX_API_KEY`, `OKX_API_SECRET`,
   `OKX_API_PASSPHRASE`).

Без ключей бот всё равно полностью работает в режиме скрининга и сигналов — просто не
будет мониторить открытые позиции (публичные рыночные эндпоинты OKX ключа не требуют).

## Как получить Telegram-бота и chat_id

1. В Telegram напиши **@BotFather** → `/newbot`, следуй шагам, получишь `TELEGRAM_BOT_TOKEN`.
2. Напиши своему новому боту любое сообщение (иначе он не сможет писать тебе первым).
3. Открой в браузере:
   `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates`
   и найди `"chat":{"id": ...}` — это `TELEGRAM_CHAT_ID`.
4. Впиши оба значения в `.env`.

Без токена/chat_id бот не упадёт — сигналы будут просто печататься в консоль.

## Структура

```
index.js                 # главный цикл
src/config.js             # чтение .env
src/okx.js                 # OKX REST v5: публичные + подписанные (read) запросы
src/indicators.js          # RSI, MACD, Supertrend, ATR
src/screener.js             # скрининг кандидатов (тикеры + OI)
src/analyzer.js              # индикаторы, гейты стратегии, скоринг, сигнал
src/messages.js               # форматирование сообщений
src/positionMonitor.js         # мониторинг открытых позиций (только чтение)
src/state.js                    # персистентное состояние (state.json, settings.json)
src/telegram.js                  # отправка в Telegram
src/server.js                     # веб-дашборд (Express): статика + JSON API
public/                            # HTML/CSS/JS дашборда
Dockerfile, .dockerignore           # сборка образа для Dokploy/Docker
docker-compose.yml                   # локальный запуск в Docker с volume
```

## Настройка стратегии

Все пороги вынесены в `.env` (фильтры скрининга, RSI-зоны, Supertrend-параметры,
кулдауны, плечо/маржа по умолчанию) — поменять поведение можно без правки кода.

## Важно

- Ликвидация в сигнале — грубая оценка (`~100/leverage %` минус небольшой буфер),
  без учёта тиров maintenance margin конкретной пары. Перед входом сверяйся с
  калькулятором OKX.
- Это не финансовый совет, а технический скринер по заданным правилам.
- Модуль мониторинга позиций **читает** позиции через приватный (подписанный) эндпоинт,
  но никогда не вызывает торговые эндпоинты — открытие/закрытие сделок остаётся
  полностью в руках пользователя.
